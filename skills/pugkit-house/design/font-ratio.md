# font-ratio

デザインカンプの px をそのまま書きながら、画面幅に応じて文字サイズを比例させる仕組み。既定では使わない。入れるかどうかの判断がこのファイルの主題になる。

## 何を解決するか

SP のカンプは 390px などの1枚しかないのに、実機の幅は 320px から 767px まで散る。カンプの px を固定値で当てると、狭い端末で文字が詰まり、広い端末で余白が間延びする。

`--font-ratio` は「いま何倍で表示すべきか」を CSS変数に持たせ、トークンの値に掛ける。カンプの数値を書くだけで、幅に応じた拡縮が付いてくる。

## どんなサイトで使うか

デザイン重視のサイトで使う。カンプの見た目を幅が変わっても保ちたい、文字と余白の比率が崩れると成立しない、というサイトが対象になる。キャンペーンサイトやブランドサイトが典型。

コーポレートサイトや、情報量が多くて読ませることが目的のサイトには入れない。文字サイズは読み手が決めるもので、画面幅で勝手に変わるとブラウザの文字サイズ設定と競合する。狭い端末で本文が縮むのは、読みやすさの面では劣化になる。

判断に迷ったら入れない。あとから入れるより、入れたものを外すほうがはるかに高くつく。

## 入れる場合に必要になるもの

換算は `_tokens.scss` で済んでいるので、書き換えるのは文字サイズのトークンだけになる。参照する側は `var(--font-size-2xl)` のままで、宣言を1つも触らない。

```scss
// 既定
--font-size-2xl: #{fn.rem(24)};

// font-ratio を入れる場合
--font-size-2xl: calc(#{fn.rem(24)} * var(--font-ratio));
```

そのうえで次の3つを足す。

| 足すもの | 中身 |
|---|---|
| `_tokens.scss` の `--font-ratio` | 既定値は `1`。カンプのアートボード幅と一致する幅で 1 になるようにする |
| 段階生成の mixin | 幅ごとに `--font-ratio` を切り替えるメディアクエリを並べる。連続的な `vw` ではなく段階にするのは、端数の丸めで文字サイズがぶれるのを避けるため |
| 印刷時のリセット | `@media print` で `--font-ratio: 1` に戻す。紙には画面幅の概念がない |

CSS変数の置換は算出値の時点で起きるため、`:root` の `--font-ratio` をメディアクエリで切り替えると、参照している全トークンが計算し直される。

代償として、トークンの値が `1.5rem` のような静的な値ではなくなり、実行時の `calc()` になる。

余白まで比率に載せるなら、px のトークンも `calc(40px * var(--font-ratio))` の形にする。文字だけ載せるか余白も載せるかを先に決めて、混在させない。混在すると文字と余白の比率がカンプと合わなくなる。

PC 側は既定で切っておく。最大幅を決めて中央寄せする構成では、文字まで拡大すると崩れやすい。

## 外すときのコスト

トークンを参照する全宣言が前提を共有するので、外すときは全体を見直すことになる。入れる判断は、実装を始める前に済ませる。
