# 着手予定の機能

やると決めていて、まだ手を付けていないもの。判断済みで今はやらないものは [todo.md](todo.md) にある。

着手するときは、この文書の該当節を読んでから始める。決め終わっている論点を蒸し返さないため。

## 共通の線引き

ここに挙げる機能は、次の問いを通したものだけを pugkit に入れる。

> テンプレートに書けば済むか。済むなら pugkit の仕事ではない。

pugkit は `<img>` を生成しない。`imageInfo()` が値を返し、タグはテンプレートが書く。
したがって `fetchpriority` / `loading` / `decoding` / `sizes` は、すべてテンプレートの担当になる。

| pugkit の担当                          | テンプレートの担当     |
| -------------------------------------- | ---------------------- |
| ファイルを作る                         | 属性を書く             |
| 作ったファイルと書いた値がずれないこと | 案件ごとの方針を決める |

この線引きで、当初案にあった「LCP 指示子の付与」と「Speculation Rules の生成」は落とした。
どちらもレイアウトに1行書けば済み、ビルドツールが持つ理由がない。

## 1. 画像の w記述子（着手中）

ここにあった仕様は [ADR 0011](adr/0011-image-widths-are-caller-driven.md) に置き換わった。
着手するときは ADR を読むこと。

覆した決定は2つある。幅の一覧は設定ではなく `imageInfo()` の呼び出し側が渡す。
dev は幅違いを起動時に作らず、リクエストされた時点で作る。
以前の仕様に書いてあった「呼び出し側から渡すと参照駆動になる」という却下理由は、
無印が glob から作られる以上この件には当たらないため、ADR で差し替えた。

実装が終わったらこの節を消す。

## 2. 出力の参照が実在するかの検査

### 目的

リンク切れと画像切れが、例外にならないまま納品される。ビルドは成功し、
HTML を1枚ずつ開くまで気づけない。CSS から `src/` の画像を参照したときの
「変換後の名前を直書きしないと壊れる」問題も、ここで拾える。

`imageInfo()` を通らずにテンプレートが `hero@400w.webp` を直書きした場合も、この検査が担当になる。
dev はリクエスト時に生成して 200 を返すが build は作らないので、この検査だけが食い違いに気づける
（[ADR 0011](adr/0011-image-widths-are-caller-driven.md)）。

### 決まっていること

静的ファイルだけを見る。ネットワークに出ない。外部URLを叩くと結果が実行のたびに変わり、
テストが書けなくなる。再現性を優先する（[ADR 0001](adr/0001-build-is-always-full.md)）。

build のみ。dev はリクエスト時ビルドなので全ページが出力に存在しない。
`assertUniqueOutputs` と同じ考え方で、build を最終の関門にする（[ADR 0005](adr/0005-abort-on-output-conflict.md)）。

既定は警告で、中止まではしない。中止するのは「正しい姿が一意に決まる」ときに限る、という
既存の使い分けに合わせる（[ADR 0008](adr/0008-config-key-mistakes-are-reported.md)）。
リンク切れは直し方が一意ではない。パスを直すのか、ファイルを置くのか、
CMS に組み込んだ後にサーバー側で解決されるのかは pugkit には分からない。

### 設定

```js
build: {
  check: {
    references: 'warn', // 'warn' | 'error' | 'off'
    markup: 'warn',     // 'warn' | 'error' | 'off'
    ignore: []          // 検査から外すパスのパターン
  }
}
```

`ignore` は CMS のテンプレートタグを含むパスのためにある。
`<?php echo $url ?>` のような文字列が属性に入る案件があり、それを誤検出で止めると何もできなくなる。

### 集める対象

| 種別 | どこから                                                                         |
| ---- | -------------------------------------------------------------------------------- |
| HTML | `href` / `src` / `srcset` の各候補 / `<source srcset>` / `<use href>` / `poster` |
| CSS  | `url()`                                                                          |

対象外にするもの。スキーム付きURL、`//` 始まり、`#` だけのアンカー、`mailto:`、`tel:`、`data:`、
空文字、`{{ }}` や `<?php` を含む文字列。

パスの解決は3経路で揃える。ここがずれると、同じ形のURLでも別のファイルを見にいく。
既存の `core/dev/page-candidates.mjs` が dev で同じ問題を解いているので、規則はそこに合わせる。
ディレクトリ指定（末尾スラッシュ）は `index.html` に読み替える。`subdir` を含んだ絶対パスを解く。

### あわせて見るもの（markup）

ページ全体を持つビルドツールにしか判定できないものだけを入れる。

- `fetchpriority="high"` が1ページに2つ以上ある。優先度指定が無意味になる
- `<img>` に `width` / `height` が無い。CLS の原因になる
- `id` の重複
- 幅記述子の `srcset` があるのに `sizes` が無い。HTML 仕様では必須で、
  無いとブラウザは `100vw` として扱い、常に最大の候補を選ぶ。
  `<source>` は後続の `img` が auto-sizes を許すときだけ省ける

テンプレート側で判定できるものは入れない。

### 触る場所

新しく `core/check-output.mjs` を置く。`Builder.build()` の最後、出力を書き終えた後に呼ぶ。
`core/output-conflicts.mjs` が「書く前の検査」なのに対して、これは「書いた後の検査」になる。

### テストで固定すること

- 実在しない参照を見つけて報告する
- 実在する参照は報告しない。相対・絶対・末尾スラッシュのディレクトリ指定を通す
- 外部URL・アンカー・`mailto:`・`data:` は報告しない
- `subdir` を指定したときも正しく解決する
- CSS の `url()` を見る。`format: 'webp'` のとき `url(hero.jpg)` が報告される
- `error` にすると build が中止する。`off` で何も見ない
- `ignore` に入れたパスは報告しない
- `fetchpriority="high"` が2つあると報告する。1つなら報告しない
- 幅記述子の `srcset` に `sizes` が無いと報告する

### 落とし穴

「無いこと」を確かめるテストは、対象が処理されていなくても通る。
報告しないことを確かめるテストには、前提として「検査自体は動いている」ことを先に assert する
（[testing.md](testing.md) の指針）。
