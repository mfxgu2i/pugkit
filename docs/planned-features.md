## 共通の線引き

どちらの機能も、次の問いを通したものだけを pugkit に入れる。

> テンプレートに書けば済むか。済むなら pugkit の仕事ではない。

pugkit は `<img>` を生成しない。`imageInfo()` が値を返し、タグはテンプレートが書く。
したがって `fetchpriority` / `loading` / `decoding` / `sizes` は、すべてテンプレートの担当になる。

| pugkit の担当                          | テンプレートの担当     |
| -------------------------------------- | ---------------------- |
| ファイルを作る                         | 属性を書く             |
| 作ったファイルと書いた値がずれないこと | 案件ごとの方針を決める |

この線引きで、当初案にあった「LCP 指示子の付与」と「Speculation Rules の生成」は落とした。
どちらもレイアウトに1行書けば済み、ビルドツールが持つ理由がない。

## 1. 画像の w記述子

### 目的

いまの `srcset` は密度記述子（`1x` / `2x`）だけを出す。表示幅がビューポートに応じて変わる画像では、
密度記述子だと過大なファイルを取りに行く。幅記述子（`400w`）と `sizes` の組み合わせが必要になる。

### 決まっていること

`sizes` は書かない。レイアウト上どの幅で表示されるかは、その場所を書いている人しか知らない。
pugkit が担うのは、どの幅の画像ファイルを実際に作るかと、`srcset` がその実在するファイルを指すことの保証。

幅の一覧は設定に持たせる。呼び出し側から渡す形にすると参照駆動になり、
CSS の `url()` から参照される画像が dist から消える事故に戻る（[ADR 0001](adr/0001-build-is-always-full.md)）。

```js
build: {
  image: {
    format: 'webp',
    sourceDensity: 2,
    widths: [], // 既定は空。従来どおり密度記述子で出す
  }
}
```

`widths` が空なら現状のまま。値が入っていたら `srcset` を幅記述子に切り替える。
密度と幅を同時に出すと `srcset` が2種類になり、テンプレート側が選べない。プロジェクト単位でどちらかにする。

原寸は無印のまま残す。`imageInfo()` を通らない参照（CSS の `url()` 直書き・OGP・favicon）を壊さないため
（[ADR 0006](adr/0006-single-source-image-density.md)）。幅の候補には無印も最大幅として含める。

原寸を超える幅は作らない。拡大しても情報は増えない。

### 出力名

`@half` と同じ族で揃える。

```
src/assets/img/hero.jpg   (1600x1200)
  ↓  widths: [400, 800, 1200]
dist/assets/img/hero.webp        (1600x1200)  ← 無印は原寸
dist/assets/img/hero@400w.webp   ( 400x300)
dist/assets/img/hero@800w.webp   ( 800x600)
dist/assets/img/hero@1200w.webp  (1200x900)
```

### 触る場所

| ファイル                    | 何をするか                                                        |
| --------------------------- | ----------------------------------------------------------------- |
| `config/defaults.mjs`       | `build.image.widths` を足す                                       |
| `config/main.mjs`           | 値を正規化する。数値の昇順・重複除去・非正の値を落とす            |
| `utils/image-density.mjs`   | `densityOutputs` の隣に幅版を置く。生成側と参照側で規則を共有する |
| `tasks/image.mjs`           | 幅ごとにリサイズして書き出す                                      |
| `transform/image-size.mjs`  | `srcset` を幅記述子で組み立てる                                   |
| `core/watcher.mjs`          | 削除側が全候補を消せること（`imageOutputPaths` を通す）           |
| `core/output-conflicts.mjs` | 幅違いも衝突検査の対象に入る（`imageOutputPaths` 経由なので自動） |

出力先の導出は `imageOutputPaths` に集約されているので、そこが幅を返すようにすれば
削除側と衝突検査は自動で追随する。ここを迂回して独自に導出しないこと。

### テストで固定すること

- `widths` が空なら出力が現状と1バイトも変わらない
- `widths` を指定したとき、実際に出たファイルと `srcset` の候補が一致する
- 原寸を超える幅は作らず、`srcset` にも並ばない
- 画像を消したとき、幅違いの出力もすべて消える
- SVG と GIF は幅の対象外（密度と同じ扱い）

### やらないこと

多形式出力（AVIF と WebP を並べて `<picture>` に出す）はこの作業に含めない。
`format` を単数から複数に変えると `imageInfo()` の返り値の形がもう一段変わり、
幅記述子と同時に動かすと差分が読めなくなる。別の作業として後から積む。

## 2. 出力の参照が実在するかの検査

### 目的

リンク切れと画像切れが、例外にならないまま納品される。ビルドは成功し、
HTML を1枚ずつ開くまで気づけない。CSS から `src/` の画像を参照したときの
「変換後の名前を直書きしないと壊れる」問題も、ここで拾える。

### 決まっていること

静的ファイルだけを見る。ネットワークに出ない。外部URLを叩くと結果が実行のたびに変わり、
テストが書けなくなる。再現性を優先する（[ADR 0001](adr/0001-build-is-always-full.md)）。

build のみ。dev はリクエスト時ビルドなので全ページが出力に存在しない。
`assertUniqueOutputs` と同じ考え方で、build を最終の関門にする（[ADR 0005](adr/0005-abort-on-output-conflict.md)）。

既定は警告で、中止まではしない。中止するのは「正しい姿が一意に決まる」ときに限る、という
既存の使い分けに合わせる（[ADR 0008](adr/0008-config-key-mistakes-are-reported.md)）。
リンク切れは直し方が一意ではない。パスを直すのか、ファイルを置くのか、
CMS に組み込んだ後にサーバー側で解決されるのかは pugkit には分からない。

### 設定

```js
build: {
  check: {
    references: 'warn', // 'warn' | 'error' | 'off'
    markup: 'warn',     // 'warn' | 'error' | 'off'
    ignore: []          // 検査から外すパスのパターン
  }
}
```

`ignore` は CMS のテンプレートタグを含むパスのためにある。
`<?php echo $url ?>` のような文字列が属性に入る案件があり、それを誤検出で止めると何もできなくなる。

### 集める対象

| 種別 | どこから                                                                         |
| ---- | -------------------------------------------------------------------------------- |
| HTML | `href` / `src` / `srcset` の各候補 / `<source srcset>` / `<use href>` / `poster` |
| CSS  | `url()`                                                                          |

対象外にするもの。スキーム付きURL、`//` 始まり、`#` だけのアンカー、`mailto:`、`tel:`、`data:`、
空文字、`{{ }}` や `<?php` を含む文字列。

パスの解決は3経路で揃える。ここがずれると、同じ形のURLでも別のファイルを見にいく。
既存の `core/dev/page-candidates.mjs` が dev で同じ問題を解いているので、規則はそこに合わせる。
ディレクトリ指定（末尾スラッシュ）は `index.html` に読み替える。`subdir` を含んだ絶対パスを解く。

### あわせて見るもの（markup）

ページ全体を持つビルドツールにしか判定できないものだけを入れる。

- `fetchpriority="high"` が1ページに2つ以上ある。優先度指定が無意味になる
- `<img>` に `width` / `height` が無い。CLS の原因になる
- `id` の重複

テンプレート側で判定できるものは入れない。

### 触る場所

新しく `core/check-output.mjs` を置く。`Builder.build()` の最後、出力を書き終えた後に呼ぶ。
`core/output-conflicts.mjs` が「書く前の検査」なのに対して、これは「書いた後の検査」になる。

### テストで固定すること

- 実在しない参照を見つけて報告する
- 実在する参照は報告しない。相対・絶対・末尾スラッシュのディレクトリ指定を通す
- 外部URL・アンカー・`mailto:`・`data:` は報告しない
- `subdir` を指定したときも正しく解決する
- CSS の `url()` を見る。`format: 'webp'` のとき `url(hero.jpg)` が報告される
- `error` にすると build が中止する。`off` で何も見ない
- `ignore` に入れたパスは報告しない
- `fetchpriority="high"` が2つあると報告する。1つなら報告しない

### 落とし穴

「無いこと」を確かめるテストは、対象が処理されていなくても通る。
報告しないことを確かめるテストには、前提として「検査自体は動いている」ことを先に assert する
（[testing.md](testing.md) の指針）。
