# pugkit アーキテクチャ方針

## ビルドモードの基本方針

### `build` コマンド（プロダクションビルド）

- **キャッシュを一切使わない** — テンプレートキャッシュ・ハッシュキャッシュは build 時には保存・参照しない
- **フルビルド** — 変更検知はせず、対象ファイルをすべて処理する
- **出力ディレクトリを毎回作り直す** — ビルド開始前に `outDir` を全削除してから書き出す

> 内容が変わったファイルだけ書き込むことはしない。必ず全ファイルを書き出す。
>
> `outDir` は pugkit が占有する。手で置いたファイル（`.htaccess`・PHP・アップロード等）は削除されるので、
> 出力に含めたいものは `public/` に置く。既存サイトへ組み込む場合は `outDir` を専用のディレクトリにして、
> デプロイ時に配置する。
>
> 作り直しを止める `build.clean` オプションは廃止した（破壊的変更）。設定に残っていても無視される。

### `dev` コマンド（開発サーバー）

- **キャッシュ・依存グラフはプロセスのメモリ上にのみ保持** — ディスクへの永続化は一切しない
- **セッション単位でリセット** — 起動（`pugkit dev`）から終了（`Ctrl+C`）までが1セッション。再起動すると `BuildContext` が新規作成され、キャッシュ・依存グラフはすべて初期状態に戻る
- **HTML はリクエスト時遅延ビルド + メモリ配信** — ウォッチャーは変更検知でキャッシュ無効化とリロード通知のみ行い、ビルドはブラウザが該当ページをリクエストした時に 1 ページ分だけ実行する。生成した HTML は `outDir` に書かず `CacheManager.pageHtmlCache` から配信する
- **Sass / Script は従来どおりイベント駆動の最小再ビルド** — 変更検知で影響エントリのみ再処理して `outDir` に書き出す
- **依存グラフは訪問時に構築** — Pug の依存グラフ（`graph` / `imageGraph`）はページが最初にリクエストされてコンパイルされた時に構築される。キャッシュされているページには必ずグラフのエッジが存在するため、パーシャル・画像の変更時は影響ページを正確に無効化できる（未訪問ページはキャッシュに無いので次回リクエストで最新ソースからビルドされる）
- **無効化は世代（epoch）管理** — ページ単位の無効化世代を持ち、ビルド実行中に無効化が入った場合は古い結果をキャッシュへ書き戻さない
- **ページ HTML キャッシュは LRU で上限つき（64MB）** — ページ数の多いサイトを延々と閲覧してもメモリが際限なく増えない。上限を超えた分は古い順に捨てるが、捨てられたページは次のリクエストで再ビルドされるだけなので正しさには影響しない（無効化とは異なり世代は進めない）
- **ビルドエラーはエラーページとして配信** — リクエスト時ビルドが失敗した場合、エラー内容 + ライブリロードスクリプト入りの 500 ページを返す（エラーはキャッシュしない）。ソース修正で自動復帰する
- **壊れたソースがあっても起動する** — Pug だけでなく Sass / Script / 画像 / SVG の初期ビルドが失敗しても、ログを出して dev サーバーは起動する。起動時に中止すると、直そうとしても起動できない状態になる
- **止める手段を持つ** — `Builder.close()` で監視・サーバー・常駐プロセス（Sass / esbuild）をすべて終了する。CLI の Ctrl+C も同じ経路を通る

## キャッシュの種類と有効範囲

すべてのキャッシュはメモリ上にのみ存在し、ディスクには保存されない。

| キャッシュ                     | 格納場所                            | dev                                        | build                                    |
| ------------------------------ | ----------------------------------- | ------------------------------------------ | ---------------------------------------- |
| Pug コンパイル済みテンプレート | `CacheManager.compiledCache`        | ✅ セッション中保持                        | ❌ 保存しない                            |
| ページ HTML（配信キャッシュ）  | `CacheManager.pageHtmlCache`        | ✅ セッション中保持（世代管理 + LRU 上限） | ❌ 使用しない（毎回生成して書き出し）    |
| 画像の寸法（imageInfo 用）     | `_imageSizeCache`（モジュール変数） | ✅ セッション中保持（画像変更時に無効化）  | ✅ プロセス中保持（1回のビルドで再利用） |

---

## 依存グラフの有効範囲

すべての依存グラフはメモリ上にのみ存在し、ディスクには保存されない。

| グラフ        | 対象                             | dev                               | build                                             |
| ------------- | -------------------------------- | --------------------------------- | ------------------------------------------------- |
| `graph`       | Pug ファイル間の include 依存    | ✅ セッション中保持・随時更新     | ✅ ビルド時に構築（次回 build では再構築）        |
| `sassGraph`   | Sass の `@use` / `@forward` 依存 | ✅ セッション中保持・随時更新     | ✅ 同上                                           |
| `scriptGraph` | JS/TS の import 依存             | ✅ セッション中保持・随時更新     | ✅ 同上                                           |
| `imageGraph`  | Pug ファイル→参照画像の依存      | ✅ レンダリング時に構築・随時更新 | ❌ 構築しない（build は全ファイル処理のため不要） |

> いずれも `BuildContext` のインスタンスプロパティ。`dev` / `build` を再実行するたびに `new BuildContext()` で初期化される。

## 出力ディレクトリへの書き込み方針

出力先は `outDir`（デフォルト: `dist`）で変更できる。

| モード    | 書き込み先                        | 動作                                                                                     |
| --------- | --------------------------------- | ---------------------------------------------------------------------------------------- |
| **build** | `outDir`                          | 出力ディレクトリを削除してから全ファイルを書き出す                                       |
| **dev**   | `cacheDir`（`outDir` は触らない） | HTML はメモリ配信で書き出さない。CSS / JS / 画像 / SVG / public のみキャッシュへ書き出す |

**`outDir` は build 専用**とし、dev は書き込みも読み出しもしない。これにより「`outDir` にあるもの = `build` の成果物」が常に成り立ち、dev のソースマップ等が本番成果物に混入しない。

dev の書き込み先は `cacheDir`（既定: `node_modules/.pugkit/dev`、`node_modules` が無ければ `.pugkit/dev`）。ツール専用のキャッシュなので**起動時に毎回中身を作り直す**。これにより前回セッションの残骸（削除済みソースの生成物）が配信されることがなく、「dev で見えているもの = 現在の src」が保証される。

> **`outDir` と `cacheDir` はどちらも中身を丸ごと削除される。** 消してはいけない場所を指定してしまう事故を防ぐため、両方に同じ検査（`utils/safe-dir.mjs`）を通す:
>
> - `outDir` — プロジェクトルート・`src`・`public`・`node_modules` を内包する、または `src`・`public` の配下であれば、設定の読み込み時にエラーで中止する
> - `cacheDir` — 上記に加えて `outDir` との重なりも拒否する。さらに削除前に、(1) pugkit が作成したディレクトリであることを目印ファイルで確認し、(2) 目印に記録された持ち主（PID）が生きていれば「別の dev サーバーが使用中」として中止する

**dev が配信するのは `src` と `public` から導かれるものだけ**とし、`outDir` は参照しない。前回ビルドの成果物が現在のソースの代わりに見えたり、`src` から削除したページが復活して見えたりするのを防ぐため。

レガシー HTML や手置きのアセットを dev でも表示したい場合は `public/` に置く。`public/` は build でも `outDir` にコピーされるので、dev と build で同じものが見える。

**出力先が衝突する構成はビルドを中止する。** 判定は `core/output-conflicts.mjs` に置き、image / svg / sprite / public を横断して一度だけ行う（衝突は相手の存在が要るので、各タスクが自分の出力先だけを見ても分からない）。**build は書き出す前に、dev は起動時に一度だけ**呼ぶ。保存のたびには走らせない（衝突は設定ミスであり、最終的な関門は build 側のため）。 `image` と `copy` は同じフェーズで並列に走るため、同じ場所に二人以上が書くと勝敗が非決定的になる。片方を黙って捨てると「置いたはずの画像が使われていない」ことに気づけないため、優先順位を決めるのではなく中止する。`public/` は「変換も縮小もせずそのまま出す」場所であり、`src/` に置いた画像は必ず変換される。

> Vite / Astro は生成物を専用ディレクトリ（`_astro/` など）へ出しファイル名をハッシュ化することで、衝突を構造的に起こらなくしている。pugkit は**出力のパスと名前を入力のまま保つ**ことを優先するため同じ手が使えず、代わりに衝突を検知して中止する。

## dev サーバーのモジュール構成

`core/server.mjs` は HTTP と SSE の結線だけを持ち、それ以外は責務ごとに分ける。

| モジュール                     | 役割                                                                         |
| ------------------------------ | ---------------------------------------------------------------------------- |
| `core/server.mjs`              | HTTP サーバー・SSE・ルーティングの結線                                       |
| `core/dev/startup.mjs`         | dev の起動シーケンス（ポート確認・キャッシュ作り直し・衝突検査・初期ビルド） |
| `core/watcher.mjs`             | chokidar の結線と、変更の種別ごとの反応                                      |
| `core/dev/page-candidates.mjs` | URL → ページ候補の展開と、ルート配下への封じ込め                             |
| `core/dev/page-source.mjs`     | URL → `src` の Pug ソース解決（パーシャルの除外を含む）                      |
| `core/dev/lazy-builder.mjs`    | リクエスト時ビルドと、同時リクエストの重複排除（世代つき）                   |
| `core/dev/client-script.mjs`   | 注入するスクリプトタグの組み立てと、差分適用可否の指紋計算                   |
| `core/dev/response.mjs`        | HTML の送出・エラーページ・静的配信の失敗の受け止め                          |
| `client/live-reload.js`        | ブラウザ側のライブリロード。実ファイルで、設定は `data` 属性で受け取る       |

**URL の解決順は sirv に合わせる**（フラットファイル優先。末尾スラッシュは除去して同順）。Pug ページ・`public` 由来の HTML・静的配信で順序が違うと、同じ URL でも別のファイルが選ばれる。展開そのものは `core/dev/page-candidates.mjs` に置き、拡張子（`.pug` / `.html`）だけを差し替えて Pug ページと既存 HTML で共有する。

**出力先の導出規則はタスク側に置き、監視側の削除処理と共有する**（`imageOutputPaths` / `svgOutputPath` / `sassOutputPath` / `scriptOutputPath` / `spriteOutputPath` / `publicOutputPath`）。生成と削除で規則がずれると、消したはずのファイルが配信され続ける。出力先の衝突検査（`core/output-conflicts.mjs`）も同じ関数を通して突き合わせる。

**常駐プロセスの後始末はタスク登録時に渡す**（`registerTask(name, { run, dispose })`）。どのタスクが常駐プロセスを持つかはタスク自身の事情なので、`Builder` は名指しせず受け取った `dispose` を呼ぶだけにする。

**拡張子の集合は `utils/image-formats.mjs` に集める**。glob（走査対象）・正規表現（変更の種別判定）・拡張子の読み替えという別々の形で必要になるため、書き下すと片方だけ増えたときに気づけない。

画像は 1 ソースが複数の密度を生むため `imageOutputPaths` は配列を返す（筆頭は必ず原寸）。**同じ理由で寸法の計算も共有する**（`utils/image-density.mjs`）。生成される画像の実寸と、HTML に焼き込む `width` / `height` がずれると CLS になる。

## build コマンドの独立性方針

dev サーバーがどんな状態であっても（不具合・キャッシュ汚染・グラフ破損など）、`build` コマンドは常に正しい出力を返せるよう、以下の方針で設計する。

**1. プロセス分離**  
`pugkit build` を実行するたびに新しい Node.js プロセスを起動する。dev サーバーが保持していたすべてのメモリ状態（`_imageSizeCache`・各依存グラフ・コンパイル済みテンプレート）を引き継がない。

**2. production モードではキャッシュを一切参照しない**  
`pugTask`（`tasks/pug.mjs`）は常に全ページを glob して処理する（変更検知による絞り込みは持たない）。`CacheManager.setPugTemplate` も production では保存しない。Sass・Script のインクリメンタル処理も `isDevelopment` の条件で保護し、production では常に全エントリーを処理する。

**3. 出力ディレクトリを完全削除**  
ビルド開始前に出力ディレクトリを削除してから再生成する。前回ビルドの残骸が混入しないようにする。

**4. 依存グラフも build では使わない**  
`imageGraph`（Pug→画像依存）は dev 専用とし、production コードパスには含めない。`sassGraph`・`scriptGraph` は build 中に再構築するが、インクリメンタル絞り込みには使わない。

## 設計の意図

- **シンプルさ優先** — build は「毎回同じ結果を出す」ことを保証する。キャッシュによる予期しない挙動を排除する
- **dev は応答性優先** — HTML はリクエストされたページだけをビルドするため、変更時の待ち時間がプロジェクトのページ数に依存しない（共有パーシャル変更でも体感は 1 ページ分のビルド時間）。成果物の整合性は build のフルビルドで担保する
- **`outDir` は pugkit が占有する** — 「`outDir` にあるもの = 直近の build の成果物」を常に成り立たせる。手で置いたファイルと混在させない代わりに、`src` から消したものが出力に残らないことを保証できる
