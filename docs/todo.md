# 既知の改善点（TODO）

優先度は「**気づけずに本番へ出るか**」で決める。壊れたことが分かるものより、静かに壊れるものを上に置く。

## 静かに壊れるもの

| 優先度 | 場所              | 内容                                                                                                                                                                                                                                                |
| ------ | ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 🔴 高  | `tasks/image.mjs` | **`src/` に置いた `.webp` / `.avif` が出力されない。** 変換対象（jpg/jpeg/png/gif）にも `svgTask` にも該当せず、`copyTask` は `public/` しか見ないため dist に出ない。一方 `imageInfo()` は寸法を読んで参照を書くので、**無警告のリンク切れ**になる |
| 🔴 高  | `tasks/svg.mjs`   | **`src` と `public` に同名の SVG があると、どちらが残るか保証がない。** `svg` と `copy` は同じフェーズで並列に走り、書き込みが後に着地した方が残る。画像は `assertUniqueOutputs` で中止するようにしたが、SVG とスプライトには同じ検査が無い         |
| 🟡 中  | `config/main.mjs` | **設定キーの誤記を黙って無視する。** `imageOptimizatoin` のような綴り違いは警告されず、既定値で動く。値の検証（`imageOptimization` / `imageSourceDensity`）は入れたが、キー名は素通りする                                                           |
| 🟡 中  | `tasks/image.mjs` | **EXIF Orientation を適用しない**（`sharp.rotate()` を呼んでいない）。縦位置で撮った写真が横向きで出力される。原寸と縮小版では一致するため 1x/2x のズレは起きない。直すなら `image-size` 側も回転後の寸法を返す必要がある                           |

## 設計として保留しているもの

判断済みで、今は直さないもの。前提が変わったら見直す。

| 場所                       | 内容                                                                                                                                                                         |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tasks/image.mjs`          | 画像は glob 全件走査で生成する（参照駆動にしない）。CSS の `url()` から参照される画像が dist から消える事故を避けるため。参照駆動にするなら Sass の `url()` 解析が前提になる |
| `core/watcher.mjs`         | dev は起動時に全画像を処理する。密度 2 で所要時間が約 +30% 増える。点数の多い案件で問題になれば、Pug と同じくリクエスト時生成へ移す                                          |
| `transform/image-size.mjs` | `srcset` は密度記述子（1x/2x）のみ。レイアウト幅に応じた最適化が要件になったら w 記述子 + `sizes` を検討する（呼び出し側 API の変更を伴う）                                  |

## 解決済み

以下は対応が済んだため一覧から外した。

- `imageOptimization` に未知の値を渡すと警告なく扱われる → 値を検証して警告し `webp` に倒すよう修正
- `src` と `public` で画像の出力先が衝突すると勝敗が非決定的 → 検知してビルドを中止するよう修正
- `imageInfo()` が `public/` 由来の画像の拡張子を読み替え、存在しないパスを返していた → 読み替えないよう修正
- `srcset` の URL に空白・カンマが入ると候補が壊れる → エスケープするよう修正
- CLI のエラー表示がコマンドごとにバラバラ（build/sprite だけスタックトレース）→ 3 コマンドで統一し、スタックは `PUGKIT_DEBUG=1` のときだけ出すよう修正
- Pug パーシャル削除時に親ページが無効化されない → `onPugUnlink` が `removeFile` の前に影響親を取得するよう修正
- `clean()` が `sassGraph` / `scriptGraph` / `imageGraph` を残す → すべて破棄するよう修正
- `computeHash` の失敗時にランダム値を返す → 到達不能なコードごと削除
- `context.patterns` のデッドコード → 削除
