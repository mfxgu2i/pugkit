# 既知の不具合

いま残っている不具合の一覧。

優先度は「気づけずに本番へ出るか」で決める。壊れたことが分かるものより、静かに壊れるものを上に置く。

意図してそうしているものはここに載せない。設計判断は `docs/adr/` にある。

## 静かに壊れるもの

ビルドも `pugkit check` も通り、本番の環境で初めて分かるもの。

| 優先度 | 場所                           | 内容                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------ | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 🟡 中  | `core/check/reference-url.mjs` | 参照の実在を `statSync` の成否だけで見るため、大文字小文字の違いを macOS と Windows で取りこぼす。`hero.webp` があるとき `Hero.webp` への参照が手元では通り、Linux のサーバーで 404 になる。直すなら `realpathSync.native` の結果と突き合わせるが、macOS の realpath は日本語のファイル名を NFD で返すので、比較の前に両側を `normalize('NFC')` に揃える必要がある                                                  |
| 🟡 中  | `tasks/image.mjs`              | EXIF Orientation を適用しない（`sharp.rotate()` を呼んでいない）。縦位置で撮った写真が横向きで出力される。sharp は既定で EXIF を落とすので出力に回転情報が残らず、ブラウザ側でも直らない。実寸は入力のままなので `width` / `height` と `srcset` の記述子はずれない。ずれるのは向きだけ。直すなら `utils/image-dimensions.mjs` も回転後の寸法を返す必要がある                                                        |
| 🟡 中  | 各タスクの glob                | `src/` に置いた対応外のファイルが無警告で消える。フォント・JSON・`.css` などは、どのタスクの glob にも掛からないので出力されず、警告も出ない。`.webp` と `.avif` だけは `tasks/image.mjs` が警告する。本番で 404 になるまで気づけない。直すなら全走査時に「どのタスクも拾わなかったファイル」を数えて知らせる                                                                                                       |
| 🟡 中  | `core/output-conflicts.mjs`    | 予約サフィックスの検知が `src/` の webp / avif に効かない。`collectOwners` が src 側で走査するのは `IMAGE_GLOB`（jpg / jpeg / png / gif）だけなので、`src/hero@400w.webp` を置いても中止しない。`public/` 側は `OUTPUT_EXT_RE` で見るため中止する。[ADR 0011](adr/0011-image-widths-are-caller-driven.md) は両方で中止すると書いている                                                                              |
| 🟡 中  | `tasks/svg-sprite.mjs`         | ファイル名とディレクトリ名をそのまま `<symbol id>` に入れるため、`&` や `<` を含む名前がスプライトを壊す。`black&white.svg` は `id="black&white"` になり、SVG は XML として解析されるので、そのスプライトのアイコンが全部表示されなくなる。ビルドも `pugkit check` も通る。空白を含む名前も `id="arrow right"` になり、`<use>` から参照できない。直すなら id に使う文字を検査するか、XML の特殊文字をエスケープする |
| 🟢 低  | `tasks/image.mjs`              | 1 枚の画像の出力を `Promise.all` でまとめて待つため、最初の失敗で待機を打ち切り、`catch` はその 1 件しかログに出さない。走り出した他の書き出しは完走するが、失敗しても記録が残らない。幅の本数が増えるほど見えない失敗が増える。結果として出力が欠けた場合は `pugkit check references` が拾う                                                                                                                       |

## 挙動が期待とずれるもの

その場で分かるか、限られた使い方でしか起きないもの。

| 優先度 | 場所                    | 内容                                                                                                                                                                                                                                                                                                                                                                     |
| ------ | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 🟡 中  | `tasks/image.mjs`       | アニメーション GIF が webp/avif モードで 1 コマ目に潰れる。sharp の `{ animated: true }` に未対応（密度の対象外にしているのはこのため）                                                                                                                                                                                                                                  |
| 🟡 中  | `tasks/svg-sprite.mjs`  | `fill` の置換が `<mask>` の中にも効く。マスクの白い塗りは「見せる範囲」を表すデータで表示色ではないため、`currentColor` になると文字色に依存する。文字色が黒だとマスクが全面透明になり、単色のアイコンでも丸ごと消える。`<clipPath>` は形しか見ないので無害                                                                                                              |
| 🟡 中  | `tasks/svg-sprite.mjs`  | アイコンの `<defs>` が持つ内部 ID にファイルごとの接頭辞を付けないので、同じ id が同一文書に並ぶ。`clipPath` や `mask` の参照が別のアイコンの定義に解決されうる。Figma の書き出しは普通ユニークな id を振るので当たりにくいが、保証はない                                                                                                                                |
| 🟢 低  | `tasks/svg-sprite.mjs`  | ルート `<svg>` の属性が `viewBox` 以外落ちる。色は CSS から当てる前提なので `fill` が落ちるのは問題ないが、`stroke-width` のように形に効く属性も一緒に落ちる。ルートに書いたアイコンだけ線の太さが変わる                                                                                                                                                                 |
| 🟢 低  | `core/server.mjs`       | カンマを含むファイル名の画像が dev で 404 になる。`decodeURIComponent` と sirv の `decodeURI` が食い違い、`encodeSrcsetUrl` が出す `%2C` を sirv が復号しないため。build では出ない                                                                                                                                                                                      |
| 🟢 低  | `utils/css-targets.mjs` | browserslist が読んだ設定をプロセス内にキャッシュするため、dev の稼働中に `.browserslistrc` を書き換えても対象ブラウザが変わらない。`.scss` を保存すれば再コンパイルは走るので、変換だけ古い対象のまま出る。直すなら問い合わせの前に `browserslist.clearCaches()` を呼ぶ。設定ファイルは監視対象外で、`pugkit.config.mjs` と同じく再起動が要る位置づけのため優先度は低い |
| 🟢 低  | `tasks/sass.mjs`        | `url()` を書き換えないため、CSS から `src/` の画像を参照するには変換後の名前を直書きする必要がある。書き換えはしない方針で、参照先が実在するかは `pugkit check references` が見る                                                                                                                                                                                        |
| 🟢 低  | `core/watcher.mjs`      | `start()` が chokidar の初期走査完了（`ready`）を待たない。起動直後に編集すると、その1回だけ取りこぼす可能性がある                                                                                                                                                                                                                                                       |
| 🟢 低  | `core/watcher.mjs`      | `public/` の画像でないファイルを Pug が `include` していると、編集してもテンプレートが無効化されない。`HANDLES_EMBEDDING` の約束を 3 つのうち 2 つが条件付きでしか果たしていないため（詳細は同ファイルの `HANDLES_EMBEDDING` のコメント）。この使い方は想定していないので優先度は低い                                                                                    |
| 🟢 低  | `config/main.mjs`       | `pugkit.config.mjs` は ESM のモジュールキャッシュに載るため、同一プロセスで2回ビルドすると設定変更が反映されない（CLI は毎回新プロセスなので実運用では無害）                                                                                                                                                                                                             |
| 🟢 低  | `cli/index.mjs`         | 対象外のオプションを付けると cac の例外がスタックトレースごと出る。`pugkit build --port 3000` で `CACError: Unknown option --port` が生のまま表示される。`fail()` は各コマンドの action 内からしか呼ばれず、引数の解釈は `cli.parse()` の中で起きるため。終了コードは 1 なので、外れているのは表示だけ                                                                   |

## 検査の取りこぼし

`pugkit check` が見ていない範囲。報告が 0 件でも、ここは確かめていない。

| 優先度 | 場所                             | 内容                                                                                                                                                                                                            |
| ------ | -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 🟢 低  | `core/check/html-references.mjs` | `style` 属性と `<style>` 要素の中の `url()` を見ない。`<script type="application/ld+json">` の中の URL も見ない。`<style>` の中身は `collectCssReferences` に流せるが、報告位置を要素の位置からずらす処理が要る |
| 🟢 低  | `core/check/html-references.mjs` | 報告する位置が属性ではなく開始タグの位置になる。htmlparser2 は属性ごとの位置を持たない。整形済みの HTML はタグごとに改行されるので実用上はほぼ同じ行を指すが、1 行に複数タグが並ぶと列がずれる                  |
| 🟢 低  | `core/check/html-references.mjs` | 手書きの `srcset` にカンマ入りのファイル名が来ると候補の分解を誤る。pugkit が出す `srcset` は `encodeSrcsetUrl` がカンマを `%2C` にするので起きない                                                             |

## 解決済み

以下は対応が済んだため一覧から外した。

- リンク切れと画像切れが例外にならないまま納品される → 出力を読んで参照の実在と HTML の妥当性を検査する `pugkit check` を追加（[ADR 0013](adr/0013-check-is-a-separate-command.md)）
- `create-pugkit` のテンプレートが `pugkit check` を通らない → 参照先の favicon と OGP 画像を `public/` に置き、下層ページの見出しを `h1` から始めるよう修正
- `srcset` が密度記述子のみで、レイアウト幅に応じた最適化ができない → `imageInfo()` に `widths` と `sizes` を渡せるようにして幅記述子を出すよう修正（[ADR 0011](adr/0011-image-widths-are-caller-driven.md)）
- 対象ブラウザが未対応のモダン構文が素通りし、そのブラウザでだけスタイルが効かない → CSS の後処理を Lightning CSS に一本化して降格するよう修正（[ADR 0010](adr/0010-css-postprocess-is-lightningcss.md)）
- 設定キーの誤記を黙って無視する → 起動時にキーを検査し、実在しないキーは警告、v1 の旧名は中止するよう修正
- `build.html` の既定が `inline: []` でインライン要素を改行し、表示に無い空白を入れていた → 上書きをやめて js-beautify の既定に任せるよう修正
- `content_unformatted` に `textarea` が無く、textarea の中身が整形されて値が変わっていた → 既定に戻すよう修正
- `siteUrl` が空のまま `Builder.url` を参照しても無警告で相対パスが入る → 参照された時に1度だけ警告するよう修正
- `engines` が `>=18.0.0` で、依存の実要求とも Node の保守期限とも合っていなかった → `>=22.0.0` に上げ、CLI の入口でも判定するよう修正
- `npm install` が EBADENGINE・非推奨・脆弱性の警告を並べる → `engines` を `>=22.22.2` に上げ（nopt の要求に合わせた）、sharp を 0.35 系に上げ、寸法の読み取りを image-dimensions に移し、テンプレートから markuplint を外すよう修正
- `icons/` のサブディレクトリに置いた SVG が、スプライトにも個別出力にも入らないまま無警告で消える → `icons/` 配下を再帰的にスプライトへ集め、`<symbol id>` を `icons/` からの相対パスにするよう修正（[ADR 0014](adr/0014-icons-are-collected-recursively.md)）
- スプライトの出力先の導出が生成側と検査側でずれ、`src/` 直下の `icons/` で衝突を取りこぼす → `iconDirOf` に集約し、生成・検査・監視が同じ規則を使うよう修正。あわせて `icons.svg` を予約名にした
- symbol の並び順が glob 依存で、環境が変わるとアイコンを触っていなくてもスプライト全体が差分になる → id の昇順に固定するよう修正
- `src/` に置いた `.webp` / `.avif` が無警告で出力されない → 全走査時に警告するよう修正（`public/` へ誘導）
- SVG・スプライトに出力先の衝突検知が無い → 検査を `core/output-conflicts.mjs` に集約し、image / svg / sprite / public を横断して見るよう修正
- `imageOptimization` に未知の値を渡すと警告なく扱われる → 値を検証して警告し `webp` に倒すよう修正
- `src` と `public` で出力先が衝突すると勝敗が非決定的 → 検知してビルドを中止するよう修正（dev は起動時に一度だけ検査してログに出す）
- `imageInfo()` のルート相対パスが `subdir` を考慮せず、`subdir` 付きの案件では書き方を問わず壊れていた → サイトルート起点の URL として解くよう修正（[ADR 0015](adr/0015-image-root-relative-paths-are-url-rooted.md)）
- `Builder.url.pathname` が `subdir` を含まず、`new URL(href).pathname` と意味が食い違っていた → 配信されるパスを返すよう修正（[ADR 0016](adr/0016-pathname-includes-subdir.md)）
- `imageInfo()` が `public/` 由来の画像の拡張子を読み替え、存在しないパスを返していた → 読み替えないよう修正
- `srcset` の URL に空白・カンマが入ると候補が壊れる → エスケープするよう修正
- CLI のエラー表示がコマンドごとにバラバラ（build/sprite だけスタックトレース）→ 3 コマンドで統一し、スタックは `PUGKIT_DEBUG=1` のときだけ出すよう修正
- Pug パーシャル削除時に親ページが無効化されない → `onPugUnlink` が `removeFile` の前に影響親を取得するよう修正
- `clean()` が `sassGraph` / `scriptGraph` / `imageGraph` を残す → すべて破棄するよう修正
- `computeHash` の失敗時にランダム値を返す → 到達不能なコードごと削除
- `context.patterns` のデッドコード → 削除
