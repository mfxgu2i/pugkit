## 設計として保留しているもの

判断済みで、今は直さないもの。前提が変わったら見直す。

確定した設計判断は `docs/adr/` にある。ここに載せるのは「やるかもしれないが今はやらない」もので、
決定そのものではない。

| 場所                        | 内容                                                                                                                                                                                                                                                                                                            |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tasks/image.mjs`           | 無印と `@half` は glob 全件走査で生成する（参照駆動にしない）。CSS の `url()` から参照される画像が dist から消える事故を避けるため。幅違いだけは参照駆動で、無印が残るので同じ事故は起きない（[ADR 0011](adr/0011-image-widths-are-caller-driven.md)）                                                          |
| `core/dev/startup.mjs`      | dev は起動時に無印と `@half` を全件処理する（`INITIAL_DEV_TASKS`）。実測で写真 40 枚あたり約 1.5 秒。点数の多い案件で問題になれば、幅違いと同じくリクエスト時生成へ移す（[ADR 0004](adr/0004-cachedir-is-not-persisted.md)）。移すなら `imageInfo()` を通らない参照が dev で 404 になる問題を別に解く必要がある |
| `tasks/image.mjs`           | 1 枚の画像の出力を `Promise.all` でまとめて待つため、1 本目の失敗で待機を打ち切る。走り出した書き出しは完走するが、2 本目以降の失敗はログに出ない。幅の本数が増えるほど見えない失敗が増える                                                                                                                     |
| `core/check/references.mjs` | 検査から外す設定を持たない。CMS がサーバー側で生成するページへのリンクは報告され続ける。`allowMissing` のような逃げ道は、除外したこと自体が忘れられる方が高くつくため、必要になってから足す（[ADR 0013](adr/0013-check-is-a-separate-command.md)）                                                              |
| `core/check/references.mjs` | 出力が古いまま検査すると、直したはずの参照が壊れていると報告される。出力の生成時刻とソースを突き合わせる判定は入れていない。判定自体が誤報を出したときに逃げ場がなくなるため                                                                                                                                    |
| `core/check/markup.mjs`     | 幅記述子の `srcset` に `sizes` が無いことを見ない。markuplint に委ねた結果、そのルールが向こうに無ければ誰も見ない。自前の項目を足すのは、markuplint 側に入らないと分かってから                                                                                                                                 |

## 解決済み

以下は対応が済んだため一覧から外した。

- `srcset` が密度記述子のみで、レイアウト幅に応じた最適化ができない → `imageInfo()` に `widths` と `sizes` を渡せるようにして幅記述子を出すよう修正（[ADR 0011](adr/0011-image-widths-are-caller-driven.md)）
- 対象ブラウザが未対応のモダン構文が素通りし、そのブラウザでだけスタイルが効かない → CSS の後処理を Lightning CSS に一本化して降格するよう修正（[ADR 0010](adr/0010-css-postprocess-is-lightningcss.md)）
- 設定キーの誤記を黙って無視する → 起動時にキーを検査し、実在しないキーは警告、v1 の旧名は中止するよう修正（[ADR 0008](adr/0008-config-key-mistakes-are-reported.md)）
- `build.html` の既定が `inline: []` でインライン要素を改行し、表示に無い空白を入れていた → 上書きをやめて js-beautify の既定に任せるよう修正（[ADR 0009](adr/0009-html-formatting-follows-js-beautify.md)）
- `content_unformatted` に `textarea` が無く、textarea の中身が整形されて値が変わっていた → 既定に戻すよう修正
- `siteUrl` が空のまま `Builder.url` を参照しても無警告で相対パスが入る → 参照された時に1度だけ警告するよう修正
- `engines` が `>=18.0.0` で、依存の実要求とも Node の保守期限とも合っていなかった → `>=22.0.0` に上げ、CLI の入口でも判定するよう修正
- `src/` に置いた `.webp` / `.avif` が無警告で出力されない → 全走査時に警告するよう修正（`public/` へ誘導）
- SVG・スプライトに出力先の衝突検知が無い → 検査を `core/output-conflicts.mjs` に集約し、image / svg / sprite / public を横断して見るよう修正
- `imageOptimization` に未知の値を渡すと警告なく扱われる → 値を検証して警告し `webp` に倒すよう修正
- `src` と `public` で出力先が衝突すると勝敗が非決定的 → 検知してビルドを中止するよう修正（dev は起動時に一度だけ検査してログに出す）
- `imageInfo()` が `public/` 由来の画像の拡張子を読み替え、存在しないパスを返していた → 読み替えないよう修正
- `srcset` の URL に空白・カンマが入ると候補が壊れる → エスケープするよう修正
- CLI のエラー表示がコマンドごとにバラバラ（build/sprite だけスタックトレース）→ 3 コマンドで統一し、スタックは `PUGKIT_DEBUG=1` のときだけ出すよう修正
- Pug パーシャル削除時に親ページが無効化されない → `onPugUnlink` が `removeFile` の前に影響親を取得するよう修正
- `clean()` が `sassGraph` / `scriptGraph` / `imageGraph` を残す → すべて破棄するよう修正
- `computeHash` の失敗時にランダム値を返す → 到達不能なコードごと削除
- `context.patterns` のデッドコード → 削除
