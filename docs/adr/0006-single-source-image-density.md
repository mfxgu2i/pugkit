# 0006. 画像は 1 ソースから密度別に生成する

## 状況

高解像度対応のために `hero.jpg` と `hero@2x.jpg` を手で 2 枚用意する運用が一般的だった。

2 枚の寸法が対応していることを人が保証する必要があり、
片方だけ差し替えると `srcset` の記述子が嘘になる。差し替え漏れも起きる。

## 決定

`src/` には最大解像度の 1 枚だけを置く。
`imageSourceDensity`（既定 2）に応じて、ビルドが縮小版を生成する。

原寸は無印のまま出し、縮小版に `@half` を付ける。

```
src/assets/img/hero.jpg   (1600x1200)
  ↓  imageSourceDensity: 2
dist/assets/img/hero.webp        (1600x1200)
dist/assets/img/hero@half.webp   ( 800x600)
```

## 理由

置くファイルが 1 枚になるので、寸法の対応が構造的に保証される。

無印を原寸のままにしたのは、`imageInfo()` を通らない参照を壊さないため。
CSS の `url()` 直書き、OGP 画像、favicon は `src` に書いた名前をそのまま使う。
無印を縮小版にすると、これらが黙って半分の画像を指すことになる。

縮小版の接尾辞を `@1x` ではなく `@half` にしたのは、
`@1x` がデザインツールの書き出し名として実在し、予約語にすると衝突するため。
`@half` は密度ではなく「原寸の半分」という変換内容を表している。

## 却下した案

### 無印を表示サイズにし、原寸に @2x を付ける

`srcset` の記述子と名前が一致して直感的になるが、
`imageInfo()` を通らない参照がすべて縮小版を指すことになる。

## 結果

生成側（`tasks/image.mjs`）と参照側（`transform/image-size.mjs`）が
同じ規則を使う必要がある。HTML に焼き込む `width` / `height` と
実際に出力された画像の寸法がずれると CLS になるため、
規則は `utils/image-density.mjs` に集めて共有する。

1 ソースが複数の出力を生むので `imageOutputPaths` は配列を返す。筆頭は必ず原寸。
削除側は原寸の寸法を知らないため、候補すべてを消せる必要がある。

縮小しても寸法が変わらない画像（1x1 など）は縮小版を作らない。
同じ寸法のファイルを 2 枚配って記述子だけ嘘になるのを防ぐ。

GIF と SVG は密度の対象外。GIF は sharp のアニメーション対応を入れていないため
縮小すると 1 コマ目に潰れる。SVG はベクターなので密度の概念が当てはまらない。

`public/` の画像は変換も縮小もされない。等倍のまま出したいものはここに置く。
