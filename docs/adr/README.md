# 設計判断の記録（ADR）

pugkit がある形になっている理由を、決定ごとに 1 ファイルで残す。

コードを読めば何をしているかは分かるが、なぜ他の選択肢を捨てたのかは読み取れない。
同じ議論を繰り返さないために、検討して却下した案もここに書く。

## 書き方

ファイル名は `NNNN-短い題名.md`。番号は連番で、欠番を作らない。

各ファイルは次の見出しを持つ。

### 状況

何に困っていたか。前提となる制約。

### 決定

何を選んだか。

### 理由

なぜそれを選んだか。

### 却下した案

検討したが採らなかったもの。採らなかった理由も書く。
前提が変われば復活しうるので、否定ではなく保留として書く。

### 結果

その決定が招いた制約や、利用者に見える影響。

この 5 つは必ず置く。判断の根拠になった計測値のように、
どれにも収まらない材料がある場合は、理由の直後に節を足してよい。

## 状態について

一度書いた ADR は書き換えない。判断が変わったときは新しい ADR を追加し、
古い方の冒頭に「NNNN で置き換えられた」と 1 行だけ加える。

決定した時点で何を知っていたかが残らないと、記録の意味がなくなるため。
