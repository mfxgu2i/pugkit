# 0005. 出力先が衝突したら中止する

## 状況

`src/icon.svg` と `public/icon.svg` が両方あると、どちらも `dist/icon.svg` に書く。

`image` / `svg` / `copy` は同じフェーズで並列に走るため、どちらが残るかは
書き込みが着地した順で決まる。実行のたびに結果が変わりうる。

画像でも、拡張子が読み替わらない構成なら同じことが起きる。
`imageOptimization: 'compress'` のとき `src/logo.png` と `public/logo.png` は
どちらも `dist/logo.png` を取り合う。

既定の `'webp'` ではこの組み合わせは衝突しない。`src` 側が `logo.webp` と
`logo@half.webp` になるため出力先が分かれる。衝突するかどうかは設定に依存する。

## 決定

出力先が衝突する構成を検知したら、ビルドを中止する。
どちらを優先するかの規則は設けない。

検査は `core/output-conflicts.mjs` に置き、image・svg・sprite・public を
横断して一度だけ行う。build は書き出す前に、dev は起動時に一度だけ呼ぶ。

## 理由

片方を黙って捨てると「置いたはずの画像が使われていない」ことに気づけない。
出力を見ても、意図した方が残っているのか偶然そうなっただけなのか分からない。

衝突は設定かファイル配置の誤りであって、正しい解決順が存在する状況ではない。
機械が勝手に決めるより、人に直してもらう方が速い。

判定をタスクの外に置いたのは、衝突には相手の存在が要るため。
各タスクが自分の出力先だけを見ても分からない。

## 却下した案

### 優先順位を決める（例: public を常に優先）

決めれば動くが、負けた側が消えたことは伝わらない。
利用者から見ると「置いたのに反映されない」だけになる。

### 生成物を専用ディレクトリに出し、ファイル名をハッシュ化する

Vite や Astro の方法で、衝突が構造的に起きなくなる。

pugkit は出力のパスと名前を入力のまま保つことを優先しているため採れない。
CSS の `url()` 直書き、OGP 画像、favicon など、
ビルドツールを通らない参照が壊れないようにするための方針で、これは譲れない。

## 結果

build は書き出す前に検査し、衝突があれば中止する。前回の成果物は残したままにする。

dev は起動時に一度だけ検査し、見つかってもログに出すだけで起動は続ける。
保存のたびには走らせない。衝突は設定ミスであり、最終的な関門は build 側だから。

検査の対象は image / svg / sprite / public の 4 つ
（`imageOutputPaths` / `svgOutputPath` / `spriteOutputPath` / `publicOutputPath`）。

CSS と JS は対象外。エントリの出力先は入力の拡張子を差し替えるだけで、
同じ名前を取り合う相手が構造上いない。

出力先の導出はタスク側が持ち、検査はそれを集めて突き合わせるだけにする。
検査が独自に導出すると、生成側と規則がずれたときに検知できなくなる。
