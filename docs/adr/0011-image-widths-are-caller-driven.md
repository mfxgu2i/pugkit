# 0011. 画像の幅は呼び出し側が決める

## 状況

[ADR 0006](0006-single-source-image-density.md) で決めたとおり、`srcset` は密度記述子
（`1x` / `2x`）だけを出していた。密度記述子は「同じ表示幅を、何倍の解像度で描くか」しか
言えない。表示幅がビューポートに応じて変わる画像では、狭い画面でも原寸に近いファイルを
取りに行くことになる。

レイアウト幅に応じた最適化には幅記述子（`400w`）と `sizes` が要る。ここで、どの幅の
ファイルを作るかを誰が決めるのかが問題になる。

pugkit は画像を glob の全件走査で生成する（[ADR 0001](0001-build-is-always-full.md)）。
参照駆動にしないのは、CSS の `url()` から参照される画像が dist から消える事故を避けるため。
幅を呼び出し側から受け取る形は、この方針と衝突するように見える。

dev には別の制約がある。HTML はリクエスト時ビルド（[ADR 0002](0002-dev-html-lazy-build.md)）
だが、画像は起動時に全件処理している。まだ開いていないページが要求する幅は、
その時点では存在しない。

## 決定

幅は `imageInfo()` の呼び出し側が渡す。設定には幅の一覧を持たない。

```pug
- const info = imageInfo('/assets/img/hero.jpg', {
    widths: [400, 800, 1200],
    sizes: '(max-width: 768px) 100vw, 800px'
  })
```

`widths` を渡さなければ従来の密度モードのまま。渡した画像だけが幅モードに入り、
返り値の `srcset` / `width` / `height` に `build.image.sourceDensity` が効かなくなる。

出力名は `@half` と同じ族で揃える。原寸は無印のまま残し、`srcset` の最大候補も兼ねる。
原寸以上の幅は作らない。

```
src/assets/img/hero.jpg   (1600x1200)
  ↓  widths: [400, 800, 1200]
dist/assets/img/hero.webp        1600x1200
dist/assets/img/hero@half.webp    800x600
dist/assets/img/hero@400w.webp    400x300
dist/assets/img/hero@800w.webp    800x600
dist/assets/img/hero@1200w.webp  1200x900
```

`@half` と `@<数字>w` はビルドが作る名前として予約する。`src/` と `public/` に
この形の画像を置いたら build を中止する。

dev は起動時に幅違いを作らず、リクエストされた時点で作る。

`sizes` の値は pugkit が決めない。呼び出し側が渡した文字列を、載せるべき要素にだけ返す。

## 理由

幅はレイアウトの都合で決まる。ヒーローとサムネイルでは必要な幅が違い、それを知っているのは
その場所を書いている人だけ。設定に一覧を置くと、全画像に同じ幅を掛けることになる。

設定に既定を置くと、それを書いた瞬間に `sizes` を書いていない画像まで幅モードに入る。
HTML 仕様では、幅記述子の `srcset` に `sizes` が無いと `100vw` として扱われる。
サムネイルでも全幅想定で候補を選ぶので、密度モードより重いファイルを取りに行く。
既定が静かに退行を招く形になる。

ADR 0001 との衝突は起きない。`BUILD_PHASES` は pug を image より先に置いているので、
build では幅の集合が src の純関数になる。無印と `@half` は従来どおり glob から作られるので、
`imageInfo()` を通らない参照が dist から消えることはない。参照駆動になるのは幅違いだけで、
幅違いを CSS の `url()` から直書きする使い方は存在しない。

`@half` を幅モードでも作り続けるのは、同じ画像を別のページが密度モードで参照しうるため。
モードは画像ごとではなく呼び出しごとに決まるので、片方のページの都合でファイルを消すと
もう片方の `srcset` が壊れる。

予約サフィックスは、幅が呼び出し側で決まると出力先を先に列挙できなくなるため。
`imageOutputPaths` が幅違いを返せない以上、衝突検査はこれを名前の規則で肩代わりするしかない。

dev のリクエスト時生成は、生成の可否を URL だけで決める。dev はページ HTML がキャッシュに
載っているとレンダリングを通らないので、収集した幅の一覧は常に不完全になる。
それに照らすと、同じ URL が開いたページによって 200 と 404 を行き来する。

## 却下した案

### 設定に全画像共通の幅一覧を持つ

Next.js の `deviceSizes`、Eleventy Image のプラグイン設定の `widths`、Nuxt Image の
`screens` はこの形をとる。実装は最も簡単で、dev と build の経路も分かれない。

採らなかったのは、上に書いた `sizes` の問題のため。既定を置いた瞬間に、意識していない
画像まで巻き込む。呼び出しごとに書かせれば、`sizes` を書く場所と幅を書く場所が同じになる。

幅の一覧が案件内で重複するようなら、名前付きプリセットを設定に置く形は後から足せる。
そのときも幅を選ぶのは呼び出し側という原則は変えない。

### dev では幅違いを作らず、無印に倒して返す

`@400w` のリクエストに原寸を返せば、生成のコストはゼロになる。

採らなかったのは、dev で見ているものと本番が変わるため。`core/server.mjs` は
public に同名の HTML があるとき dev でも Pug を返さない、という選び方を既にしている。
「dev で見たページが本番に出ない」を避けるための判断で、ここでも同じ線を引く。

### width / height に表示サイズを返す

密度モードの `width` は原寸を `sourceDensity` で割った値、つまり意図した表示幅だった。
幅モードでも同じ値を返せば、`widths` を足しても見た目が変わらない。

採らなかったのは、幅を二重に主張することになるため。幅記述子は実ピクセル幅で語り、
どの幅で表示するかは `sizes` が決める。そこに属性で別の幅を書くと、
`src` の実寸とも `srcset` の記述子とも一致しない数字が HTML に残る。

## 結果

`width` 属性の意味がモードで変わる。密度モードでは表示サイズ、幅モードでは原寸の実寸になる。
HTML 仕様では `width` / `height` は `aspect-ratio` だけでなく CSS の `width` / `height` の
presentational hint にも写る。優先度は最も低い出自なので作成者スタイルシートが必ず勝つが、
CSS が幅を決めていない画像は属性の値そのままで描画される。
幅モードは CSS で幅を決めることが前提になる。

レイアウトシフトは起きない。読み込み前に確保される箱は比率から決まり、比率は実寸から導く。

dev と build のアセット一致が弱まる。従来は dev の起動直後に build と同じファイルが
揃っていたが、幅違いはページを開いた後に揃う。

`imageInfo()` を通らずにテンプレートが `hero@400w.webp` を直書きすると、dev では
リクエスト時に生成されて 200 が返り、build では生成されないので 404 になる。
この食い違いは `docs/planned-features.md` の参照検査が拾う担当になる。

予約サフィックスは、衝突していない場合でも build を中止する。支給素材に
`banner@1200w.jpg` という名前が混ざっているだけで止まる。中止の条件を
「正しい姿が一意に決まるとき」に置く既存の使い分け（[ADR 0008](0008-config-key-mistakes-are-reported.md)）
からすると広いが、書き直し方は別名にする以外に無いので一意ではある。
dev は起動する。既存の出力先衝突と同じく、build を最終の関門にする
（[ADR 0005](0005-abort-on-output-conflict.md)）。

[ADR 0004](0004-cachedir-is-not-persisted.md) が保留にしていた「画像も Pug と同じく
リクエスト時生成へ移す」を、幅違いについてだけ先に実装する形になる。無印と `@half` を
同じく移すかは決めていない。移すなら、`imageInfo()` を通らない参照が dev で 404 になる
問題を別に解く必要がある。

出力先の導出を `imageOutputPaths` に一本化する不変条件が、幅違いについては緩む。
生成は収集した幅、削除は出力ディレクトリの走査、衝突検査は名前の予約と、
3つの規則に分かれる。名前の規則そのものは `utils/image-density.mjs` に集めて共有する。
