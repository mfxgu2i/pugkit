# 0013. 出力の検査は build と分けたコマンドにする

## 状況

リンク切れと画像切れは、例外にならないまま納品される。ビルドは成功し、
HTML を 1 枚ずつ開くまで気づけない。

CSS の `url()` はとくに静かに壊れる。`tasks/sass.mjs` は `url()` を書き換えないので、
`format: 'webp'` の案件で `url(hero.jpg)` と書いても CSS は正常に出力され、
背景画像だけが出ない。

当初は build の最後に検査を挟む案だった。`assertUniqueOutputs` と同じく
build を最終の関門にする形になる。

## 決定

`pugkit check` を独立したコマンドにする。build は検査をしない。

検査は既にある出力を読む。ビルドは走らせない。出力が無ければ検査せずに中止し、
`pugkit build` を促す。

項目は id を可変長の位置引数で受ける。指定が無ければ全項目。

```bash
pugkit check                     # 全部
pugkit check references          # 参照の実在だけ
```

あわせて、プロジェクトルートを指す位置引数を 4 コマンドすべてから廃止する。
`check` は項目 id を可変長の位置引数で受けるので、先頭の引数をルートに使えない。
`check` だけ形が違うと「他のコマンドで書ける引数が check には無い」と読めるため、
`dev` / `build` / `sprite` からも外して cwd を見る形に揃える。

位置引数を無くすと、綴りを間違えたコマンドが既定コマンドに落ちる。
`pugkit chekc` が黙って dev サーバーを起動しないよう、知らないコマンドは中止する。

## 理由

ビルドを止める検査は、既存案件に入れた初日に切られる。

過去の負債が残っているリポジトリで今の更新を出そうとすると、
関係のない箇所まで直さないとビルドが通らなくなる。そうなると検査は無効化され、
無効化された検査は無いのと同じになる。止めない形にする方が長く生き残る。

`build` の中に置かなかったので、`build.check` のような設定も持たない。
有効・無効は「そのコマンドを実行するかどうか」で表現される。走らなかった理由を
2 箇所探さずに済む。

ビルドを含めないのは、今ある出力を検査する手段を残すため。本番に上げた成果物や
同僚がビルドしたものを検査できる。CI では `pugkit build && pugkit check` と並べれば済む。
build は画像処理を含むので、検査だけしたいときに毎回それを待つ形にすると使われなくなる。

## 参照の実在は自前、マークアップは markuplint

`references` は pugkit にしか書けない。`format: 'webp'` のとき
`url(hero.jpg)` が壊れることは、変換後の名前を知っている側にしか判定できない。

`markup` は markuplint に渡す。pugkit の依存には含めず、利用者のプロジェクトに
あるものを使う（optional peer）。設定も pugkit は持たず、markuplint が自分で見つけるものに従う。
pugkit が別バージョンを連れてくると HTML 仕様の版が二重になり、エディタの表示と
検査の結果が食い違う。対象ブラウザを browserslist に委ねているのと同じ理由（[ADR 0010](0010-css-postprocess-is-lightningcss.md)）。

markuplint に渡すのはソースの `.pug` ではなく出力の `.html` にする。
markuplint の Pug 対応はコンポーネントをまたぐ構造を追い切れない。
報告位置が dist の行番号になる代わりに、実際に配信される形で判定できる。

## 却下した案

### build の最後に検査を挟む

見落としが構造的に起きない。ビルドすれば必ず検査される。

負債のある案件で更新が出せなくなる。既定を警告に留めれば止まらないが、
今度は毎ビルド警告が流れ、読まれなくなる。検査の結果は、見ようとしたときに
まとめて読める方が扱いやすい。

### check の中でビルドしてから検査する

常に最新の出力を見られる。dist が古いまま検査して、直したはずの参照が
壊れていると報告される事故が起きない。

今ある出力を検査できなくなる。画像処理を毎回待つことにもなる。
古い dist を検査する事故は、`pugkit build && pugkit check` と並べる習慣で防げる。

### 検査するページを絞る引数を持つ

負債の多いディレクトリを外して、今回触った範囲だけを見られる。

除外したこと自体が忘れられる。コマンドを実行しないという選択肢が既にあるので、
絞り込みが無くても負債に足を引っ張られない。項目が増える見込みがあるため、
位置引数は項目の選択に使う。

### markuplint を pugkit の依存に含める

入れた瞬間に動く。設定を書かなくても検査が始まる。

`@markuplint/*` と HTML 仕様データがまるごと付いてきて、検査を使わない利用者にも
インストールの重さがかかる。既に markuplint を入れているプロジェクトでは
版が二重になる。

## 結果

build は検査をしないので、`pugkit check` を実行しないプロジェクトでは
リンク切れが今までどおり出荷される。検査の実行は利用者の判断に委ねられる。

出力が古いまま検査すると、直したはずの参照が壊れていると報告される。
出力の生成時刻とソースを突き合わせる判定は入れていない。その判定自体が
誤報を出したときに逃げ場がなくなるため。

除外の設定を持たないので、CMS がサーバー側で生成するページへのリンクは
報告され続ける。`allowMissing` のような逃げ道は、必要になってから足す。

位置引数を廃止したので、monorepo で別ディレクトリのプロジェクトを叩くには
`cd` が要る。オプションは後から足せるが位置引数は足せないので、
必要になったら `--root` を加える。

出力ディレクトリが在りさえすれば検査は走る。中断した build が残した空の dist では
違反ゼロになるため、検査対象が 1 件も無かったことを表示で伝える。
