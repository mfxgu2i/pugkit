# 0014. icons 配下は再帰的に 1 つのスプライトにまとめる

## 状況

`icons/` の扱いが 3 箇所で食い違っていた。

| 場所                        | icons 配下の見方                               |
| --------------------------- | ---------------------------------------------- |
| `tasks/svg-sprite.mjs`      | 直下の `*.svg` だけをスプライトに集める        |
| `tasks/svg.mjs`             | `**/icons/**` を丸ごと個別出力の対象外にする   |
| `core/output-conflicts.mjs` | `**/icons/**/*.svg` をスプライトの材料とみなす |

`src/assets/icons/social/x.svg` はスプライトにも個別出力にも入らない。
ビルドは成功し、警告も出ず、本番で 404 になるまで気づけない。

出力先の導出も生成側とずれていた。`src/icons/` のようにルート直下に置くと、
検査側は `dist/icons/icons.svg` を、生成側は `dist/icons.svg` を見ていた。

`icons.svg` はスプライトの出力名だが、`icons/` ディレクトリが無ければ利用者が
同じ名前の SVG を置ける。後からディレクトリを足した時点で出力を取り合う。

## 決定

`icons/` 配下の SVG は、サブディレクトリも含めて再帰的に 1 つのスプライトにまとめる。

`<symbol id>` は `icons/` からの相対パスから拡張子を除いたものにする。
直下に置いた SVG は従来どおりファイル名がそのまま id になる。

`icons/` の中の `icons/` は、別のスプライトにせず外側のスプライトに含める。

どのアイコンがどのスプライトに属するかの導出は `tasks/svg-sprite.mjs` の
`iconDirOf` に集約し、生成・検査・監視の 3 箇所が同じ規則を使う。

`icons.svg` を予約名にする。`icons/` ディレクトリの有無に関わらず、
`src/` と `public/` に同じ名前のファイルを置かせない。

symbol は id の昇順で並べる。glob が返す順のままにすると、同じ入力でも
ファイルシステムによって並びが変わり、出力のバイト列が環境に依存する。

## 理由

黙って消えるのが最も悪い。置いたはずの SVG が出力に無いことは、
参照が 404 になるまで分からない。どちらのタスクが拾うかを決めれば消えなくなる。

`icons/` に置いた時点で「スプライトに入れる」という意思表示になっている。
深さで扱いを変えると、境界がディレクトリ構造に依存して覚えにくい。

id を相対パスにすると、同名のファイルを別のディレクトリに置いても衝突しない。
分類のためにサブディレクトリを切る動機と、id の一意性が両立する。

導出を 1 箇所に集めたのは、ADR 0005 と同じ理由。検査や後始末が独自に導出すると、
生成側と規則がずれたときに検知できず、消し残しや取りこぼしになる。

予約は ADR 0011 と同じ肩代わり。衝突の突き合わせだけに任せると、
`icons/` ディレクトリが存在するときしか検知できない。
今日は通って明日は止まるより、置いた時点で止める方が直しやすい。

## 却下した案

### id はファイル名のままにして、重複したら中止する

README の「ファイル名がそのまま id になる」という契約が変わらない。
`social/x.svg` と `brand/x.svg` が並んだら ADR 0005 と同じく中止する。

分類のためにディレクトリを切る動機と正面から衝突するので採らなかった。
分けたのに同じ名前を置けないなら、分ける意味が薄い。

### サブディレクトリはスプライトに含めず、個別の SVG として出力する

`tasks/svg.mjs` の除外を直下だけに狭める形。id の衝突は起きない。

`icons/` に置いたのにスプライトに入らないものができる。
扱いがディレクトリの深さで変わり、`icons/` という名前が意味しているものと
出力の実際がずれるので採らなかった。

### icons.svg を予約せず、衝突の突き合わせだけに任せる

`icons/` ディレクトリがあるときは今でも検知できる。

無いときに検知できないのが問題で、後から足した人にしか症状が出ない。
足した本人には、自分の変更が原因だと分かりにくい。

## 結果

`icons/` のサブディレクトリに SVG を置いていたプロジェクトでは、
これまで出力されていなかったアイコンがスプライトに入る。
参照は `<use href="assets/icons.svg#social/x">` の形で書ける。

`src/` か `public/` に `icons.svg` があるプロジェクトは build が中止する。
別の名前に変える必要がある。

並び順を id の昇順に固定したので、同じ入力なら環境をまたいでも同じバイト列が出る。
`dist/` を版管理に入れている場合や、内容を比べて納品する場合に差分が出なくなる。

同じ id が並んだときにどちらの定義が勝つかも、順序で決まるようになった。
スプライト内の `<symbol id>` は相対パスなので重複しないが、
アイコンの中の `<defs>` が持つ内部 ID は今も重複しうる。
これは `docs/todo.md` に残る別の不具合で、直すときの前提がこれで揃う。
